# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Minimal, terminal-styled GeoIP lookup web app. Web port of the Python CLI at
[BatistaFelipe/geoip](https://github.com/BatistaFelipe/geoip). Deployed on
Vercel at `geoip.felipebatista.dev`. Open source (MIT).

Stack: **Next.js 16** (App Router, Turbopack, Cache Components enabled) · React 19 · TypeScript 5 · Tailwind CSS 4 · Jest 29 + ts-jest.

## Commands

```bash
npm run dev            # dev server on :3000
npm run build          # production build (next build via Turbopack)
npm run start          # run the production build
npm run lint           # ESLint
npm test               # Jest suite (unit + route handler integration)
npm run test:coverage  # Jest with coverage, scoped to src/lib and src/app/api
```

Single-test invocation:

```bash
npx jest tests/resolve.test.ts
npx jest -t "returns 400 for private IP targets"   # by test name
```

CI (`.github/workflows/ci.yml`) runs lint → test → build on every push and PR
against `main` using Node 22.

## Architecture

### Request flow

Client (`LookupForm.tsx`) submits `GET /api/lookup?target=<ip-or-host>`.
The route handler orchestrates four library modules in strict order — **the
order matters** for both security and correctness:

1. `rate-limit.ts::rateLimit(clientIp)` — in-memory sliding window, 20 req/min
   per IP. Short-circuits with 429 before any resolution happens.
2. `isValidTarget(target)` — charset/length validation on the raw input.
3. `resolve.ts::resolveTarget(target)` — if `target` is already a valid IP
   (via `node:net isIP`), returned as-is. Otherwise resolved through
   `node:dns/promises lookup` with a 5s abort timeout. Throws `ResolveError`.
4. `resolve.ts::isPublicIp(ip)` — **SSRF guard**. Rejects private, loopback,
   link-local, CGNAT, multicast and reserved ranges for both IPv4 and IPv6
   (including `::ffff:`-mapped IPv4). This runs **after** DNS resolution so a
   hostname pointing to a private IP is still blocked.
5. `ipinfo.ts::getIpInfo(ip)` — HTTPS call to ipinfo.io with 10s abort timeout.
   Appends `?token=` only if `IPINFO_TOKEN` is present (tokenless free tier
   works for low volumes).

Each library module exports a typed error class (`ResolveError`,
`IpInfoError`) with a discriminated `code` field. The route handler maps those
codes to HTTP status: `dns_failed`→400, `timeout`→504, `rate_limited`→429,
`upstream_error`→502. Successful responses carry `Cache-Control: no-store`.

### Why no `export const dynamic`/`runtime` in `route.ts`

`next.config.ts` has `cacheComponents: true`. Under Cache Components, the
legacy Route Segment Config exports (`dynamic`, `runtime`, `revalidate`) are
**rejected at build time**. Dynamicness is inferred automatically from runtime
API usage (reading `request.url`, headers, etc.). Do not add them back.

### UI

`src/app/page.tsx` is a Server Component composing `LookupForm` (client) and
`Footer` (server). `Footer.tsx` contains three fixed lines mandated by the
original brief — do not change the copy without checking with the owner. The
whole UI uses Tailwind `font-mono` with `whitespace-pre` + `tabular-nums` to
keep label columns aligned like real terminal output.

### Testing

`tests/*.test.ts` are mapped via `@/*` → `src/*` through `jest.config.js`
`moduleNameMapper`. The route handler test (`tests/route.test.ts`) mocks the
three library modules with `jest.requireActual(...)` spread + `jest.fn()`
overrides, then imports the handler **after** the mocks. This is the only
pattern that works with the current ts-jest + CommonJS output — don't
restructure it to top-level ESM imports.

## Non-obvious constraints

- `AGENTS.md` is auto-regenerated by `next dev`; committing the current
  content keeps the tree clean. Do not delete it in isolation.
- `.env.local.example` is explicitly unignored in `.gitignore` (there's a
  `!` exception). The broad `.env*` pattern would otherwise swallow it.
- Scaffold was done with `create-next-app --empty --disable-git`. The
  `src/` layout, `@/*` alias, and ESLint flat config are the result; the
  repo expects them.
- Never commit directly to `main`. Branch names follow `feat/`, `fix/`,
  `refactor/` prefixes. Conventional Commits for messages, English only.
- Browser never talks to ipinfo.io directly — all upstream calls go through
  `/api/lookup` so DNS resolution, SSRF checks, and any future token stay
  server-side.
